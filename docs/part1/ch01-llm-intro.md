## 1. LLM 的本质：预测下一个 token

LLM 的核心能力只有一个：**给定一段文本，预测下一个 token 的概率分布。**

```
输入： "今天天气真"
输出概率分布： 好 0.62 / 不错 0.15 / 热 0.08 / ...
选出 "好" → 拼回输入 → "今天天气真好" → 再预测下一个 ...
```

这个“预测一个、拼回去、再预测”的循环叫**自回归生成（Autoregressive Generation）**。生成 500 个 token，模型就要跑 500 次前向计算。

### 为什么“猜下一个词”能变聪明？

要在海量文本上都猜准，模型必须学会对应的能力：

| 句子 | 要猜准需要 |
|---|---|
| “法国的首都是 ___” | 知识 |
| “3 + 5 × 2 = ___” | 计算、推理 |
| `def fib(n): if n < 2: return ___` | 懂代码 |

当参数量和数据量足够大时，这些能力会**涌现**出来。

### 能力边界

本质是概率模型，所以：

- 输出的是“听起来最像”的答案，不一定正确 → **幻觉**
- 只见过训练截止前的数据 → **知识过时**
- 只能看到上下文窗口内的内容 → **长文本记忆有限**

### 💬 讨论

**Q1：既然只选概率最高的词，为什么同一个问题问两遍回答不一样？**

> **我的回答：** 每次跑的随机种子不一样。
>
> **点评：方向对，但还差一层。** 模型每次给出的概率分布是一样的，随机性出在**采样（sampling）**这一步：
>
> - **贪心解码（greedy）**：永远选概率最高的词，结果固定
> - **随机采样**：按概率“掷骰子”
> - **temperature**：调节分布的尖锐程度，越接近 0 越接近贪心，越大越随机
> - **top-k / top-p**：只在概率最高的若干候选里抽
>
> 随机种子决定的是骰子怎么掷。
>
> 冷知识：即使 temperature = 0，在 GPU 上批量推理时结果也可能有细微差异，因为不同请求拼进同一个 batch 时，浮点运算顺序会变。SGLang 专门做过“确定性推理”来解决这个问题。

**Q2：生成 500 个字要跑 500 次，这些计算里有重复工作吗？**

> **我的回答：** 有大量重复。猜一个、拼回去、再猜的时候，前面已经算好的东西可以复用，前面的上下文是不变的。
>
> **点评：完全正确，这就是 KV Cache 的核心思想。** 精确地说：
>
> - 能复用的是每个历史 token 在注意力层里算出的 **K（键）和 V（值）向量**
> - 能复用的原因是**因果掩码（causal mask）**：每个 token 只能看见它前面的 token，后面新增的 token 不会改变前面 token 的 K、V
> - 所以每步只需算新 token 的 Q、K、V，再让新 token 的 Q 与缓存中的所有 K、V 做注意力
>
> ```
> 没有 KV Cache：第 n 步重算前 n 个 token → 总计算量 ≈ O(n²)
> 有 KV Cache：  第 n 步只算 1 个新 token  → 每步计算量大幅下降
> 代价：所有历史 token 的 K、V 都要存在显存里 → 显存占用不断增长
> ```

## 2. 推理的成本与延迟

有了 KV Cache，推理分成两个阶段，这是整个课程最重要的划分之一：

| 阶段 | 做什么 | 特点 | 对应指标 |
|---|---|---|---|
| **Prefill（预填充）** | 一次性读入整段 prompt，算出所有 token 的 KV | 多个 token **并行**计算，**计算密集** | **TTFT**（首 token 延迟） |
| **Decode（解码）** | 逐个生成新 token | 每步只算 1 个 token，但要读全部权重和 KV Cache，**访存密集** | **TPOT**（每个输出 token 的耗时） |

几个关键事实：

- 高并发时，GPU 显存的 **70% 以上**可能被 KV Cache 占用，限制了并发数和上下文长度
- 显存不够时缓存会被丢弃，之后需要**重复计算**，单位 token 成本可能提高 2～3 倍
- 体验目标：TPOT 最好不超过 150 ms，也就是比人的阅读速度快

推理框架要解决的核心问题：**在有限的显存里，尽可能多、尽可能快地服务请求。**

### 💬 讨论

**Q3：附带 1 万字文章、只回答“是/否”的请求，主要耗时在哪？写 3000 字小说呢？**

> **我的回答：** 前者主要在 Prefill，后者主要在 Decode。
>
> **点评：正确。** 补充一点：prefill 的 token 可以**并行**计算，1 万字可能一两秒就完成；decode 必须**串行**，一个算完才能算下一个。所以同样多的 token，decode 通常比 prefill 慢得多。

**Q4：很多请求都带同一段 2000 token 的系统提示词，推理框架怎么省钱？**

> **我的回答：** 缓存系统提示词的 KV 进行复用。
>
> **点评：正确，这就是 SGLang 的招牌特性：前缀缓存（Prefix Caching）**。SGLang 的实现叫 **RadixAttention**，用一棵基数树管理缓存：
>
> ```
>                     [系统提示词 2000 tokens]   ← 所有请求共享，只算一次
>                    /           |            \
>           [用户A问题]      [用户B问题]      [用户C问题]
>               |
>         [A的第2轮对话]  ← 多轮对话也能复用上一轮的 KV
> ```
>
> 关键限制：**必须是从头开始完全相同的前缀才能复用。** 因为一个 token 的 K、V 取决于它前面的**所有** token，开头差一个字，后面所有 KV 都会变。
>
> 实用启示：写 prompt 时把**固定内容放前面、变化内容放后面**，缓存命中率更高。

## 3. Transformer 核心组件

一个 Transformer Block 的结构（原始论文的 Post-Norm 版本）：

```
x ──┬──→ [多头注意力] ──→ (+) ──→ [LayerNorm] ──┬──→ [FFN] ──→ (+) ──→ [LayerNorm] ──→ 下一层
    │                      ↑                       │                ↑
    └──────── 残差 ─────────┘                       └───── 残差 ─────┘
```

### 3.1 位置编码

**为什么需要：** 注意力本质是加权求和，本身不关心顺序。只看词向量的话，“我 爱 你”和“你 爱 我”是同一组向量，模型分不清谁爱谁。

**正余弦位置编码**直接加到词向量上：

$$
X = \text{Embedding}(token) + PE(pos)
$$

$$
PE_{(pos,2i)} = \sin\left(\frac{pos}{10000^{2i/d_{\text{model}}}}\right), \quad
PE_{(pos,2i+1)} = \cos\left(\frac{pos}{10000^{2i/d_{\text{model}}}}\right)
$$

**用钟表来理解：**

- 秒针转得快，能区分相邻两秒，但 60 秒后会转回原位
- 分针转得慢，能区分更长的跨度，但相邻两秒几乎看不出变化
- 多根指针组合起来，任何时刻都有唯一读数

位置编码就是一个有 $d_{\text{model}}/2$ 根指针的钟表，每对 sin/cos 是一根：

- 小 $i$ → 转得快（高频）→ 区分**相邻位置**
- 大 $i$ → 转得慢（低频）→ 区分**远距离位置**

::: tip 两个关键设计
1. **sin 和 cos 配对**：$(\sin\theta, \cos\theta)$ 是单位圆上的一个点，能唯一确定角度
2. **多频率**：不同维度用不同频率，组合后每个位置的编码唯一
:::

现代模型（LLaMA、Qwen、DeepSeek）基本都用 **RoPE（旋转位置编码）**：不再把位置“加”到向量上，而是对 Q、K 按位置做“旋转”。

#### 💬 讨论

**Q5：为什么要同时用 sin 和 cos，只用 sin 不行吗？**

> **我的回答：** sin 在 0 到 2π 之间同一个值会出现 2 次，加上 cos 后每个值就唯一了。
>
> **点评：完全正确。** 几何上看，只看纵坐标（sin）时，一条水平线和单位圆交于两点；加上横坐标（cos）后，一个点唯一对应一个角度。
>
> sin/cos 配对还有一个更重要的好处：**相对位置可以表示为线性变换。** 由和角公式：
>
> $$
> \begin{pmatrix}\sin(\theta+\delta)\\ \cos(\theta+\delta)\end{pmatrix} =
> \begin{pmatrix}\cos\delta & \sin\delta\\ -\sin\delta & \cos\delta\end{pmatrix}
> \begin{pmatrix}\sin\theta\\ \cos\theta\end{pmatrix}
> $$
>
> 也就是说，“往后挪 k 格”等于“在圆上转一个只和 k 有关的固定角度”。这正是 RoPE（**旋转**位置编码）名字的由来。

**Q6：把位置信息“加”到词向量上有什么潜在问题？**

> **我的回答：** 词向量的语义计算会变得更加复杂。
>
> **点评：抓到了问题，可以说得更具体。** 把注意力分数展开：
>
> $$
> (x_i + p_i)^\top W (x_j + p_j) =
> \underbrace{x_i^\top W x_j}_{\text{语义↔语义}} +
> \underbrace{x_i^\top W p_j + p_i^\top W x_j}_{\text{语义↔位置（噪声）}} +
> \underbrace{p_i^\top W p_j}_{\text{位置↔位置}}
> $$
>
> 1. 出现“词 A 和位置 7 有多相关”这类**无意义的交叉项**，模型要花力气学会忽略
> 2. 我们真正关心的是**相对距离**，这里混入的却是**绝对位置**
> 3. **长度外推差**：训练时只见过位置 0～2047，推理时遇到位置 5000 效果就会崩
>
> **RoPE** 只旋转 Q 和 K，两个旋转后向量的点积只取决于角度差，也就是**相对位置**。交叉项消失了，还能通过 YaRN、NTK 等插值方法扩展到很长的上下文。

### 3.2 多头注意力

**一句话理解：** 每个 token 发出一个“问题”（Q），每个 token 都挂着一个“标签”（K）和一份“内容”（V）。问题和标签越匹配，就从那份内容里拿得越多。

$$
\text{Attention}(Q,K,V) = \text{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}\right)V
$$

1. $QK^\top$：每个 token 的问题和所有标签做点积，得到 `[seq, seq]` 的相关性打分
2. $\div \sqrt{d_k}$：缩放，防止分数过大
3. softmax：每一行变成和为 1 的权重
4. $\times V$：按权重对内容加权求和

例子：“**小猫** 坐在垫子上，因为 **它** 很累”。“它”的 Q 在问“我指代的是谁”，“小猫”的 K 匹配度高，于是“它”的新表示里融入了大量“小猫”的信息。

**多头：** 把 512 维切成 8 份、每份 64 维，8 组 Q/K/V 各自独立做注意力，拼接后再乘 $W^O$。好比 8 个人从不同角度读同一句话，总计算量和单头差不多，表达能力强很多。

| 原始论文参数 | 值 |
|---|---|
| $d_{\text{model}}$ | 512 |
| 头数 $h$ | 8 |
| $d_k = d_v$ | 64 |
| $\sqrt{d_k}$ | 8 |

**和推理的联系：** 要缓存的就是每一层、每个头的 K 和 V：

$$
\text{KV Cache 大小} = 2 \times \text{层数} \times \text{KV 头数} \times d_k \times \text{序列长度} \times \text{每个数的字节数}
$$

#### 💬 讨论

**Q7：为什么要除以 $\sqrt{d_k}$？**

> **我的回答：** 防止某个分数权重过大、小分数权重过小。对训练的影响不知道。
>
> **点评：前半对，后半补充如下。**
>
> ```
> 打分 [3, 0.2, 0.1]   → softmax ≈ [0.89, 0.05, 0.05]   有主次
> 打分 [30, 2, 1]      → softmax ≈ [1.00, 0.00, 0.00]   几乎 one-hot
> ```
>
> **对训练的影响是梯度消失：** softmax 饱和后，输入怎么微调输出都几乎不变，梯度接近 0，模型学不动。
>
> **为什么偏偏是 $\sqrt{d_k}$：** 假设 q、k 各分量均值 0、方差 1，点积 $\sum_{i=1}^{d_k} q_i k_i$ 是 $d_k$ 项之和，方差为 $d_k$，标准差为 $\sqrt{d_k}$。除以 $\sqrt{d_k}$ 正好把方差拉回 1。

**Q8：MQA 让 8 个 Q 头共用 1 组 K、V，为了解决什么？代价是什么？**

> **我的回答：** 解决 KV 缓存过大；代价是会多出没意义的交叉项。
>
> **点评：动机对，代价错了。** 交叉项是 Q6 里位置编码相加带来的问题，和这里无关。
>
> - ✅ 动机：KV Cache 直接缩小到 1/8，能放下更多上下文和并发，decode 时要读的数据也少很多
> - ❌ 正确的代价：**表达能力下降**。8 个头还能各自“提问”，但只能看同一份“资料”，视角多样性打了折扣，效果可能下降
>
> 于是有了折中方案：
>
> ```
> MHA：8 个 Q 头 ↔ 8 组 KV                    效果最好，KV 最大
> GQA：8 个 Q 头 ↔ 2 组 KV（每 4 个 Q 共用 1 组） 折中 ← LLaMA 2/3、Qwen
> MQA：8 个 Q 头 ↔ 1 组 KV                    KV 最小，效果损失最大
> ```
>
> DeepSeek 的 **MLA** 更进一步，把 KV 压缩成低维潜在向量来缓存。
>
> **主线：很多模型架构的演进，本质上是在为推理效率让路。**

### 3.3 残差连接与层归一化

**残差连接**：$\text{output} = x + \text{Layer}(x)$

- 每层只学一个“修正量”，不需要改时学成 0 即可，最差也能保持恒等映射
- 给梯度一条“高速公路”，反向传播时可以直通浅层

**层归一化（LayerNorm）**：对每个 token 自己的向量做“减均值、除标准差”，再乘 $\gamma$、加 $\beta$

$$
\text{LayerNorm}(v) = \gamma \cdot \frac{v - \mu}{\sigma} + \beta
$$

- 让每层输出保持在稳定范围，防止数值越传越大或越传越小
- 现代模型多用 **RMSNorm**：去掉减均值，只除以均方根，更省计算

#### 💬 讨论

**Q9：为什么 Pre-Norm 训练深层网络比 Post-Norm 更稳定？**

$$
\text{Post-Norm: } \text{LN}(x + F(x)) \qquad \text{Pre-Norm: } x + F(\text{LN}(x))
$$

> **我的回答：** Post-Norm 从输出到输入的路径上挡着 LN；Pre-Norm 从输出到输入有直接的 x，中间没有其他东西，输出能看到“一手资料”。
>
> **点评：正确，“一手资料”的说法很形象。** 小修正：Post-Norm 的输出和输入也有联系，只是每层都**隔着一个 LN**。展开 L 层：
>
> $$
> \text{Pre-Norm: } x_L = x_0 + F_1 + F_2 + \dots + F_L
> $$
>
> 输入被原封不动地加到输出里，梯度中永远有一项“1”直通第一层。
>
> $$
> \text{Post-Norm: } x_L = \text{LN}(\dots\text{LN}(\text{LN}(x_0 + F_1) + F_2)\dots)
> $$
>
> 梯度要穿过 L 个 LN，层数多了容易爆炸或消失，所以需要小心的学习率预热（warmup）。
>
> Pre-Norm 也不是完胜：深层的 $x$ 越来越大，每层加的 $F$ 显得微不足道，深层“贡献变小”。所以后来出现了双重归一化等折中方案。

### 3.4 前馈网络（FFN）

$$
\text{FFN}(x) = \max(0, xW_1 + b_1)W_2 + b_2
$$

流程：512 维 → 线性层 → 2048 维 → ReLU → 线性层 → 512 维

- **注意力**负责 token **之间**交换信息（“它”去看“小猫”）
- **FFN** 负责每个 token **自己**消化信息，各位置独立计算，一般认为大量“知识”存在这里
- 现代模型中 FFN 约占 **2/3 的参数量**；**MoE** 把一个大 FFN 拆成多个“专家”，每个 token 只激活其中几个

**为什么必须有非线性：** $xW_1W_2 = x(W_1W_2)$，两个线性层叠起来还是一个线性层。

#### 💬 讨论

**Q10：decode 阶段，长上下文和短上下文时，注意力和 FFN 谁是瓶颈？**

> （当时没有回答，记录参考答案）
>
> decode 每步只处理 1 个 token，瓶颈不在计算，而在**从显存搬数据**：
>
> - FFN 读**模型权重**，大小固定，与上下文长度无关
> - 注意力读 **KV Cache**，大小随上下文线性增长
>
> 所以：**短上下文 → FFN（权重读取）是主要开销；长上下文 → 注意力（KV Cache 读取）成为瓶颈。** 这也是后面要学 FlashAttention、PagedAttention 等“注意力后端”的原因。

### 3.5 从本课基础到 SOTA

| 组件 | 本课基础 | 演进路线 |
|---|---|---|
| 整体架构 | Encoder-Decoder | → Decoder-only → MoE |
| 位置编码 | 正余弦 | → 可学习 → ALiBi → RoPE → NoPE |
| 注意力 | MHA | → MQA → GQA → MLA → NSA / DSA |
| 归一化 | LayerNorm（Post-Norm） | → RMSNorm、Pre-Norm、QK-Norm |
| 激活函数 | ReLU | → GeLU → SwiGLU |
| KV 处理 | 无缓存 | → KV Cache → KV 量化 → PagedAttention |
| 精度 | FP32 | → BF16 → FP8 → INT4 |

## 4. 关键基础概念

| 概念 | 一句话 | 和推理的关系 |
|---|---|---|
| **Token** | 分词器切出的最小单位，模型处理的是整数 ID | 计费、延迟、显存都按 token 计 |
| **Embedding** | 把 token ID 查表变成向量 | 模型的第一步 |
| **参数** | 可学习的权重，70B = 700 亿个浮点数 | 70B × 2 字节（BF16）= 140 GB，单张 80 GB 显卡放不下 → 多卡并行或量化 |
| **自回归生成** | 逐个生成 token | decode 只能串行 |
| **上下文窗口** | 一次最多处理的 token 数 | 窗口越长，KV Cache 越大 |

应用层概念的关系：

```
Prompt（怎么问） ⊂ Context（给模型看的全部信息）
                       ↑
                     RAG（从外部检索资料，填进 Context）

Agent = 模型（大脑） + Harness（手脚和神经系统） + Skill（操作手册）
```

Agent 会反复调用模型，每轮都带着越来越长、且前缀高度重复的上下文，所以**前缀缓存在 Agent 场景里收益特别大**。

## 5. 结业测验

### 第 1 题：LLM 的核心能力是什么？为什么“预测下一个 token”能带来丰富的能力？

> **我的回答：** 核心能力是预测下一个 token。每个预测任务对应的能力不同，要求模型在训练中理解并学会不同任务对应的能力，比如编程、写作、翻译。
>
> **点评：✅ 很好。** 可以补上关键词**规模**：只有参数和数据足够大，这些能力才会涌现。

### 第 2 题：自注意力为什么需要位置编码？正余弦编码怎么提供位置信息？

> **我的回答：** 没有位置编码时，打乱一句话的顺序，模型的理解是一样的。正余弦编码通过 sin/cos，sin 一个周期内有两个相同值，除以 cos 后就不同了。
>
> **点评：⚠️ 前半对，后半有一处错误和一处遗漏。**
>
> - ❌ 不是“除以 cos”，而是**和 cos 配对**。$\sin/\cos = \tan$，周期是 π，重复得更厉害
> - ⚠️ 遗漏了**多频率**：不同维度用不同频率，组合后每个位置才有唯一编码，最后**加到**词向量上

### 第 3 题：残差连接和层归一化各自的作用？

> **我的回答：** 残差连接能把梯度连起来，层归一化可以统一每一层的数值范围。
>
> **点评：✅ 正确。** 展开一点：残差还让每层只学“修正量”，最差保持恒等映射；层归一化让训练更稳定。

### 加分题：为什么推理框架这么关心 KV Cache？

> **自回归**：每次生成一个 token，需要前面所有 token 的信息
> → **注意力**：新 token 的 Q 要和所有历史 token 的 K、V 计算
> → **因果掩码**：历史 K、V 不会变 → 可以缓存（**KV Cache**）
> → **显存**：KV Cache 随上下文长度和并发数线性增长，常占 70% 以上显存
> → **推理框架**的核心任务是管好这块显存：不浪费（PagedAttention）、能复用（RadixAttention）、能压缩（GQA/MLA、KV 量化），从而实现**更多并发、更低延迟、更低成本**

## 6. 我自己推出来的东西 & 待巩固

**自己推出来的：**

- 公共前缀可以复用 → Prefix Caching / RadixAttention
- 长输入卡在 prefill，长输出卡在 decode
- Pre-Norm 的残差路径更通畅

- softmax 饱和 → 梯度消失
